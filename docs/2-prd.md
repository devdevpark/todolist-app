## 1. 프로젝트 개요

### 목적

카테고리 및 종료일(dueDate) 기반으로 개인 할 일을 체계적으로 등록·관리·추적할 수 있는 반응형 웹 애플리케이션을 제공한다.

### 배경

개인 생산성 도구 수요가 증가하고 있으나, 기존 할일 관리 도구는 다음과 같은 한계를 가진다.

- 카테고리별 분류 기능이 없거나 유연성이 부족하다.
- 마감일 경과에 따른 상태 자동 구분(OVERDUE) 기능이 미흡하다.
- 개인화된 카테고리를 자유롭게 정의·관리하는 기능을 제공하지 않는다.

### 해결 문제

| # | 문제 | 해결 방향 |
|---|------|-----------|
| 1 | 카테고리 분류 불편 | 사용자가 직접 카테고리를 생성·수정·삭제하고 할일에 연결 |
| 2 | 마감일 상태 시각화 미흡 | PENDING / COMPLETED / OVERDUE 상태를 명확히 구분하여 표시 |
| 3 | 개인화 카테고리 부재 | 사용자별 독립 카테고리 관리 제공 (사용자 간 공유 불가) |

## 2. 사용자 페르소나

### 페르소나 A: 김철수 (20대 직장인)

| 항목 | 내용 |
|------|------|
| 나이 | 26세 |
| 직업 | 스타트업 마케터 |
| 기기 | 업무용 노트북 + 스마트폰 |
| 사용 환경 | 출퇴근 지하철 + 사무실 |

**주요 니즈**
- 업무·개인 할일을 카테고리로 나눠 한눈에 파악하고 싶다.
- 오늘 마감인 할일과 기한이 지난 할일을 즉시 확인하고 싶다.
- 모바일에서도 빠르게 할일을 등록·체크할 수 있어야 한다.

**Pain Point**
- 기존 앱은 카테고리 기능이 없어 업무/개인 할일이 뒤섞인다.
- 마감일이 지난 항목이 눈에 띄지 않아 놓치는 경우가 많다.

### 페르소나 B: 박소영 (30대 가정주부)

| 항목 | 내용 |
|------|------|
| 나이 | 34세 |
| 직업 | 프리랜서 번역가 (재택) |
| 기기 | 가정용 데스크탑 + 태블릿 |
| 사용 환경 | 주로 데스크탑, 이동 시 태블릿 |

**주요 니즈**
- 가사·육아·번역 업무를 카테고리별로 분리하여 관리하고 싶다.
- 완료한 할일과 아직 남은 할일을 명확하게 구분해서 보고 싶다.
- 직관적인 UI로 별도 학습 없이 바로 사용할 수 있어야 한다.

**Pain Point**
- 역할이 다양한 만큼 할일이 뒤섞여 우선순위 파악이 어렵다.
- 완료 취소(되돌리기) 기능이 없는 앱에서 실수가 잦았다.

## 3. 서비스 범위

### In Scope

| 영역 | 세부 내용 |
|------|-----------|
| 할일 관리 | 할일 등록, 조회, 수정, 삭제, 완료 처리, 완료 취소, 상태(PENDING / COMPLETED / OVERDUE) 표시 |
| 카테고리 관리 | 카테고리 등록, 수정, 삭제, 색상 지정, 카테고리별 할일 필터링 |
| 사용자 정보 관리 | 회원가입, 로그인, 로그아웃, ADMIN의 사용자 목록 조회 및 계정 활성/비활성 처리 |

### Out of Scope

| 제외 기능 | 비고 |
|-----------|------|
| 푸시 알림 / 이메일 알림 | Phase 2 이후 검토 |
| 반복 일정 (매일 / 매주 등) | Phase 2 이후 검토 |
| 데이터 내보내기 (CSV, PDF 등) | Phase 2 이후 검토 |
| 할일 공유 / 협업 | 개인용 앱으로 설계, 공유 기능 없음 |
| 다크모드 | Phase 2 구현 예정 |
| 다국어 지원 | Phase 2 구현 예정 |
| 소셜 로그인 (OAuth) | 범위 외 |
| 파일 첨부 | 범위 외 |

## 4. 기능 요구사항

### 4.1 인증 (Authentication)

| FR-ID | 기능명 | 설명 | 관련 BR |
|-------|--------|------|---------|
| FR-01 | 회원가입 | username(4~20자, 영문·숫자)과 password(최소 4자)를 입력하여 USER 계정을 생성한다. username 중복 시 오류 메시지를 표시한다. | BR-01, BR-11 |
| FR-02 | 로그인 | username과 password를 입력하여 인증 후 JWT 토큰을 발급받는다. 비활성화 계정은 로그인 불가 메시지를 표시한다. | BR-01, BR-12 |
| FR-03 | 로그아웃 | 클라이언트 측 JWT 토큰을 제거하고 로그인 화면으로 이동한다. | BR-01 |
| FR-04 | 인증 보호 라우팅 | 비인증 사용자가 인증 필요 경로에 접근 시 로그인 화면으로 리다이렉트한다. | BR-01 |

### 4.2 할일 관리 (Todo)

| FR-ID | 기능명 | 설명 | 관련 BR |
|-------|--------|------|---------|
| FR-05 | 할일 등록 | title(필수, 최대 200자), description(선택, 최대 1000자), categoryId(선택), dueDate(선택)를 입력하여 할일을 생성한다. 생성 시 status는 PENDING으로 설정된다. | BR-02, BR-09, BR-10 |
| FR-06 | 할일 목록 조회 | 로그인 사용자의 할일 목록을 표시한다. 카테고리 필터와 상태 필터(PENDING / COMPLETED / OVERDUE)를 지원한다. OVERDUE 판별은 서버 기준 시각으로 수행한다. | BR-02, BR-03, BR-07 |
| FR-07 | 할일 상세 조회 | 특정 할일의 title, description, category, dueDate, status, createdAt, completedAt을 표시한다. | BR-02 |
| FR-08 | 할일 수정 | title, description, categoryId, dueDate를 수정한다. title은 필수값이다. | BR-02, BR-10 |
| FR-09 | 할일 삭제 | 특정 할일을 영구 삭제한다. 삭제 전 확인 다이얼로그를 표시한다. | BR-02 |
| FR-10 | 할일 완료 처리 | PENDING 또는 OVERDUE 상태의 할일을 COMPLETED로 변경한다. 완료 처리 시 completedAt을 기록한다. | BR-02, BR-08 |
| FR-11 | 할일 완료 취소 | COMPLETED 상태의 할일을 PENDING으로 되돌린다. completedAt을 초기화한다. | BR-02, BR-08 |
| FR-12 | OVERDUE 상태 표시 | dueDate가 현재 서버 시각을 경과한 PENDING 할일은 OVERDUE로 표시한다. DB 저장값이 아닌 런타임 판별 결과를 UI에 반영한다. | BR-07 |

## 5. 비기능 요구사항

| NFR-ID | 분류 | 요구사항 | 상세 |
|--------|------|----------|------|
| NFR-01 | 보안 | 비밀번호 암호화 저장 | password는 bcrypt 등 단방향 해시로 암호화하여 DB에 저장한다. 평문 저장 금지. |
| NFR-02 | 인증 | JWT 인증 방식 | HS-512 알고리즘 기반 JWT를 사용한다. 인증 토큰은 클라이언트에서 관리한다. |
| NFR-03 | 데이터 격리 | 사용자 간 데이터 접근 차단 | 모든 API는 요청자의 userId를 검증하여 타 사용자 데이터 접근을 서버에서 차단한다. |
| NFR-04 | 시간 기준 | OVERDUE 판별 기준 | 서버 기준 시각(UTC)을 사용한다. 클라이언트 시각을 판별 기준으로 사용하지 않는다. |
| NFR-05 | 플랫폼 | 반응형 웹 지원 | 모바일(375px 이상) 및 데스크탑(1280px 이상) 해상도를 모두 지원하는 반응형 레이아웃을 제공한다. |
| NFR-06 | 성능 | API 응답 시간 | 일반 CRUD API의 P95 응답 시간은 500ms 이하를 목표로 한다. |
| NFR-07 | 가용성 | 초기 데이터 | 시스템 최초 실행 시 ADMIN 계정(admin / admin)이 자동 생성된다. |
| NFR-08 | 접근성 | 브라우저 지원 | Chrome, Edge, Safari 최신 버전을 지원한다. |
| NFR-09 | UI | 디자인 일관성 | Tailwind CSS 유틸리티 클래스를 기반으로 일관된 UI를 구성한다. |
| NFR-10 | 확장성 | 다크모드 / 다국어 | Phase 2 구현 예정으로, Phase 1 설계 시 확장 가능한 구조를 유지한다. |

## 8. 제약사항 및 가정

### 데이터 제약

| 필드 | 제약조건 |

| Todo.categoryId | nullable (카테고리 미지정 허용) |
| Todo.dueDate | nullable |
| Todo.completedAt | 완료 처리 시 기록, 완료 취소 시 null 초기화 |

### 비기능 제약

- TypeScript는 Phase 1에서 사용하지 않는다.
- OVERDUE 상태는 DB에 저장하지 않으며, 서버에서 응답 시 dueDate와 현재 시각을 비교하여 런타임으로 판별한다.
- 기본 admin 계정은 삭제 및 비활성화가 불가하다.
- 사용자 간 카테고리 공유는 허용하지 않는다.

### 초기 데이터 (Seed)

| 항목 | 값 |
|------|-----|
| username | admin |
| password | admin |
| role | ADMIN |
| isActive | true |

## 9. 용어 정의

| 용어 | 정의 |
|------|------|
| Todo | 사용자가 등록하는 할일 항목. title, dueDate, status, category 등의 속성을 가진다. |
| Category | 사용자가 직접 생성하는 할일 분류 단위. 이름과 색상코드를 가지며 사용자별로 독립 관리된다. |
| PENDING | 할일이 등록된 초기 상태. 완료 처리 또는 OVERDUE 판별 전까지 유지된다. |
| COMPLETED | 사용자가 완료 처리한 상태. completedAt이 기록된다. 완료 취소 시 PENDING으로 전환된다. |
| OVERDUE | dueDate가 현재 서버 시각을 경과한 PENDING 상태. DB에 저장되지 않으며 런타임에 판별된다. |
| dueDate | 할일의 종료일(마감일). 선택 입력값이며 OVERDUE 판별 기준이 된다. |
| completedAt | 할일이 COMPLETED 상태로 전환된 시각. 완료 취소 시 null로 초기화된다. |
| isActive | 사용자 계정의 활성 여부. false인 경우 로그인이 불가하다. |
| ADMIN | 시스템 전체를 관리하는 역할. 전체 사용자 및 할일 조회, 계정 활성/비활성 처리 권한을 가진다. |
| USER | 일반 사용자 역할. 본인 소유의 할일과 카테고리에 대한 CRUD 권한을 가진다. |
| JWT | JSON Web Token. HS-512 알고리즘을 사용하는 인증 토큰 방식. |
| colorCode | 카테고리 식별을 위한 hex 형식 색상값 (예: #FF5733). |
| BR | Business Rule. 시스템이 반드시 준수해야 하는 비즈니스 규칙. |
| FR | Functional Requirement. 시스템이 제공해야 하는 기능 요구사항. |
| NFR | Non-Functional Requirement. 성능·보안·플랫폼 등 품질 속성 요구사항. |
