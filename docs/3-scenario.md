## 1. 개요

### 목적

본 문서는 TodoList 애플리케이션의 주요 사용자 행동 흐름을 시나리오 단위로 정의한다. 각 시나리오는 페르소나·사전 조건·단계별 액터 행동·시스템 응답·사후 조건으로 구성되며, 기능 요구사항(FR) 및 비즈니스 규칙(BR)과의 추적성을 유지한다.

- 개발팀은 본 문서를 기준으로 기능 구현 범위와 예외 처리 방식을 확인한다.
- QA팀은 본 문서를 기반으로 테스트 케이스를 도출한다.
- 이해관계자는 사용자 관점의 서비스 흐름을 검토하고 요구사항 완전성을 확인한다.

## 2. 정상 시나리오 (Happy Path)

### SC-HP-01: 신규 사용자 회원가입 및 첫 로그인

**페르소나**: 신규 사용자 (서비스 최초 접속)
**사전 조건**: 사용자가 브라우저를 통해 서비스 URL에 접속한 상태이며 계정이 없다.
**관련 기능**: FR-01, FR-02, FR-04
**관련 규칙**: BR-01, BR-11

#### 시나리오 흐름

| 단계 | 액터 행동 | 시스템 응답 |
|------|-----------|------------|
| 1 | 서비스 URL에 접속한다. | 비인증 상태이므로 로그인 화면으로 리다이렉트한다. (FR-04) |
| 2 | 로그인 화면에서 "회원가입" 링크를 클릭한다. | 회원가입 화면으로 이동한다. |
| 3 | username(`chulsoo`)과 password(`pass1234`)를 입력하고 가입 버튼을 클릭한다. | username 형식(4~20자) 및 중복 여부를 검증한다. 유효하면 USER 계정을 생성하고 로그인 화면으로 이동시킨다. (FR-01) |
| 4 | 로그인 화면에서 username(`chulsoo`)과 password(`pass1234`)를 입력하고 로그인 버튼을 클릭한다. | 자격증명을 검증하고 JWT 토큰을 발급한다. 클라이언트에 토큰을 저장하고 할일 목록 화면으로 이동시킨다. (FR-02) |
| 5 | 할일 목록 화면이 표시됨을 확인한다. | 인증된 사용자의 할일 목록 화면을 렌더링한다. (현재 등록된 할일 없음) |

**사후 조건**:
- `chulsoo` 계정이 USER 역할로 시스템에 등록된다.
- isActive는 `true`로 설정된다.
- 클라이언트에 JWT 토큰이 저장되어 인증 상태가 유지된다.
- 사용자는 할일 목록 화면에 위치한다.

### SC-HP-02: 카테고리 생성 후 할일 등록 (김철수 페르소나)

**페르소나**: 김철수 (20대 직장인, 스타트업 마케터) — 업무와 개인 할일을 카테고리로 분리하여 관리하려 한다.
**사전 조건**: 김철수는 `chulsoo` 계정으로 로그인된 상태이다. 등록된 카테고리 및 할일이 없다.
**관련 기능**: FR-13, FR-14, FR-05, FR-06
**관련 규칙**: BR-02, BR-04, BR-06, BR-09, BR-10

#### 시나리오 흐름

| 단계 | 액터 행동 | 시스템 응답 |
|------|-----------|------------|
| 1 | 상단 네비게이션에서 "카테고리 관리" 메뉴를 클릭한다. | 카테고리 관리 화면으로 이동한다. |
| 2 | "카테고리 추가" 버튼을 클릭하고 name(`업무`), colorCode(`#3B82F6`)을 입력한 후 저장한다. | 동일 사용자 내 카테고리명 중복 여부를 검증한다. 유효하면 `업무` 카테고리를 생성하고 목록에 표시한다. (FR-13) |
| 3 | "카테고리 추가" 버튼을 다시 클릭하고 name(`개인`), colorCode(`#10B981`)을 입력한 후 저장한다. | `개인` 카테고리를 생성하고 목록에 표시한다. 카테고리 목록에 `업무`, `개인` 두 항목이 표시된다. (FR-14) |
| 4 | 할일 목록 화면으로 이동하여 "할일 등록" 버튼을 클릭한다. | 할일 등록/수정 화면으로 이동한다. |
| 5 | title(`마케팅 기획안 초안 작성`), description(`Q2 캠페인 전략 포함`), categoryId(`업무`), dueDate(`2026-04-29`)를 입력하고 저장한다. | title 필수값 여부를 검증한다. 유효하면 status를 PENDING으로 설정하여 할일을 저장하고 할일 목록 화면으로 이동한다. (FR-05) |
| 6 | 할일 목록 화면에서 등록된 할일을 확인한다. | `마케팅 기획안 초안 작성` 항목이 `업무` 카테고리, PENDING 상태로 목록에 표시된다. (FR-06) |
| 7 | "할일 등록" 버튼을 클릭하여 두 번째 할일 title(`장보기`), categoryId(`개인`), dueDate 미입력 후 저장한다. | 할일을 PENDING 상태, categoryId 지정, dueDate null로 저장한다. |

**사후 조건**:
- `업무`, `개인` 카테고리 2개가 `chulsoo` 소유로 생성된다.
- `마케팅 기획안 초안 작성`(업무 카테고리, dueDate 2026-04-29), `장보기`(개인 카테고리, dueDate null) 할일 2개가 PENDING 상태로 저장된다.

### SC-HP-03: 카테고리 필터로 할일 확인 및 완료 처리

**페르소나**: 김철수 (20대 직장인) — 업무 카테고리 할일만 필터링하여 완료 처리하려 한다.
**사전 조건**: `chulsoo` 계정으로 로그인된 상태이다. SC-HP-02 시나리오 완료 후 `업무`, `개인` 카테고리와 각 카테고리 할일이 존재한다.
**관련 기능**: FR-17, FR-06, FR-10
**관련 규칙**: BR-02, BR-08

#### 시나리오 흐름

| 단계 | 액터 행동 | 시스템 응답 |
|------|-----------|------------|
| 1 | 할일 목록 화면에서 카테고리 필터를 "전체"로 설정한 상태를 확인한다. | `마케팅 기획안 초안 작성`, `장보기` 두 할일 모두 표시된다. (FR-06) |
| 2 | 카테고리 필터에서 `업무`를 선택한다. | `업무` 카테고리에 속한 `마케팅 기획안 초안 작성`만 표시된다. `장보기`는 목록에서 숨겨진다. (FR-17) |
| 3 | `마케팅 기획안 초안 작성` 항목의 완료 버튼을 클릭한다. | 해당 할일의 status를 COMPLETED로 변경하고 completedAt을 현재 서버 시각으로 기록한다. (FR-10) |
| 4 | 할일 목록에서 `마케팅 기획안 초안 작성` 항목의 상태를 확인한다. | 해당 항목이 COMPLETED 상태로 표시된다. |
| 5 | 카테고리 필터를 "전체"로 변경한다. | `마케팅 기획안 초안 작성`(COMPLETED), `장보기`(PENDING) 두 항목이 모두 표시된다. |

**사후 조건**:
- `마케팅 기획안 초안 작성`의 status가 COMPLETED로 변경된다.
- `마케팅 기획안 초안 작성`의 completedAt에 처리 시각이 기록된다.
- `장보기`는 PENDING 상태를 유지한다.

### SC-HP-04: OVERDUE 할일 확인 및 완료 처리 (박소영 페르소나)

**페르소나**: 박소영 (30대 가정주부, 프리랜서 번역가) — 마감일이 지난 할일을 확인하고 완료 처리하려 한다.
**사전 조건**: `soyoung` 계정으로 로그인된 상태이다. `번역 업무` 카테고리가 존재하며, `번역 초안 제출` 할일이 dueDate `2026-04-27`(현재 서버 시각 이전)로 PENDING 상태로 등록되어 있다.
**관련 기능**: FR-12, FR-06, FR-10
**관련 규칙**: BR-07, BR-08, BR-02

#### 시나리오 흐름

| 단계 | 액터 행동 | 시스템 응답 |
|------|-----------|------------|
| 1 | 할일 목록 화면에 접속한다. | 서버가 현재 시각(2026-04-28)과 각 할일의 dueDate를 비교한다. dueDate `2026-04-27`이 경과한 `번역 초안 제출`을 OVERDUE로 런타임 판별하여 목록에 OVERDUE 상태로 표시한다. (FR-12) |
| 2 | OVERDUE 상태로 표시된 `번역 초안 제출` 항목을 확인한다. | 해당 항목이 OVERDUE 배지 또는 시각적 강조와 함께 표시된다. |
| 3 | `번역 초안 제출` 항목의 완료 버튼을 클릭한다. | OVERDUE 상태의 할일을 COMPLETED로 변경하고 completedAt을 현재 서버 시각으로 기록한다. (FR-10) |
| 4 | 할일 목록에서 `번역 초안 제출` 항목의 상태를 확인한다. | 해당 항목이 COMPLETED 상태로 표시된다. OVERDUE 배지가 사라진다. |

**사후 조건**:
- `번역 초안 제출`의 status가 COMPLETED로 변경된다.
- `번역 초안 제출`의 completedAt에 처리 시각이 기록된다.
- OVERDUE 상태는 DB에 저장되지 않으며, 이후 목록 조회 시 COMPLETED로 표시된다.

### SC-HP-05: 완료 취소 후 할일 재활성화

**페르소나**: 박소영 (30대 가정주부) — 실수로 완료 처리한 할일을 되돌리려 한다.
**사전 조건**: `soyoung` 계정으로 로그인된 상태이다. `육아` 카테고리에 `어린이집 준비물 챙기기` 할일이 COMPLETED 상태로 존재하며 completedAt이 기록되어 있다.
**관련 기능**: FR-11, FR-06
**관련 규칙**: BR-02, BR-08

#### 시나리오 흐름

| 단계 | 액터 행동 | 시스템 응답 |
|------|-----------|------------|
| 1 | 할일 목록 화면에서 COMPLETED 상태의 `어린이집 준비물 챙기기` 항목을 확인한다. | 해당 항목이 COMPLETED 상태로 표시된다. |
| 2 | `어린이집 준비물 챙기기` 항목의 완료 취소 버튼을 클릭한다. | 해당 할일의 status를 PENDING으로 변경하고 completedAt을 null로 초기화한다. (FR-11) |
| 3 | 할일 목록에서 `어린이집 준비물 챙기기` 항목의 상태를 확인한다. | 해당 항목이 PENDING 상태로 표시된다. completedAt 정보가 사라진다. |
| 4 | 할일 상세 화면으로 이동하여 completedAt 필드를 확인한다. | completedAt 값이 null(미기록)로 표시된다. (FR-07) |

**사후 조건**:
- `어린이집 준비물 챙기기`의 status가 PENDING으로 변경된다.
- `어린이집 준비물 챙기기`의 completedAt이 null로 초기화된다.
- dueDate가 현재 서버 시각을 경과한 경우, 다음 목록 조회 시 OVERDUE로 런타임 판별될 수 있다.

### SC-HP-06: 카테고리 삭제 시 할일 보존 확인

**페르소나**: 김철수 (20대 직장인) — 불필요해진 카테고리를 삭제하면서 해당 할일이 보존되는지 확인하려 한다.
**사전 조건**: `chulsoo` 계정으로 로그인된 상태이다. `임시` 카테고리가 존재하며, 해당 카테고리에 `임시 메모` 할일이 PENDING 상태로 연결되어 있다.
**관련 기능**: FR-16, FR-06, FR-14
**관련 규칙**: BR-05

#### 시나리오 흐름

| 단계 | 액터 행동 | 시스템 응답 |
|------|-----------|------------|
| 1 | 카테고리 관리 화면으로 이동하여 `임시` 카테고리를 확인한다. | `임시` 카테고리가 목록에 표시된다. (FR-14) |
| 2 | `임시` 카테고리의 삭제 버튼을 클릭한다. | 삭제 확인 다이얼로그를 표시한다. ("이 카테고리를 삭제하면 연결된 할일의 카테고리가 해제됩니다. 계속하시겠습니까?") |
| 3 | 확인 다이얼로그에서 "삭제" 버튼을 클릭한다. | `임시` 카테고리를 삭제한다. 해당 카테고리에 속한 `임시 메모`의 categoryId를 null로 설정한다. 할일 자체는 삭제하지 않는다. (FR-16, BR-05) |
| 4 | 카테고리 관리 화면에서 카테고리 목록을 확인한다. | `임시` 카테고리가 목록에서 제거된다. |

**사후 조건**:
- `임시` 카테고리가 시스템에서 완전히 삭제된다.
- `임시 메모` 할일은 categoryId가 null로 변경된 채 PENDING 상태로 보존된다.

- 기본 admin 계정에 대한 비활성화 처리는 클라이언트 UI와 서버 양 단에서 모두 차단된다.

**예외 처리**: 서버 측 검증과 더불어 클라이언트 측 UI에서도 사전 차단(disabled 처리 또는 안내 문구 표시)을 적용하여 불필요한 API 요청을 방지한다.
