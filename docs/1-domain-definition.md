## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | TodoList |
| 유형 | 개인별 할일 관리 웹 애플리케이션 |
| 목적 | 카테고리 및 종료일 기반으로 할 일을 체계적으로 관리 |
| 대상 사용자 | 개인 사용자, 시스템 관리자 |

---

## 2. 문제 정의

### 현재 문제점

- 기존 할일 관리 앱은 카테고리별 분류 기능이 부재하거나 불편함
- 종료일(마감일) 기반의 일정 시각화 및 상태 구분 기능이 미흡함
- 개인화된 카테고리를 자유롭게 정의하고 관리할 수 없음

### 해결 방향

- 사용자가 직접 카테고리를 생성·관리하여 할 일을 분류 (**UC-08, BR-04, BR-06**)
- 할 일의 상태(미완료 / 완료 / 기한 초과)를 명확히 구분하여 표시 (**UC-03~05, BR-07, BR-08**)
- 인증 기반 접근 제어로 개인 데이터 보호 (**UC-01~02, BR-01, BR-02**)

## 3. 핵심 도메인 개념

### 3.1 엔티티 및 속성

#### User (사용자)

| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 고유 식별자 |
| username | String | 로그인 아이디 (unique) |
| password | String | 암호화된 비밀번호 |
| role | Enum | 역할 (ADMIN / USER) |
| createdAt | DateTime | 가입일시 |
| isActive | Boolean | 계정 활성 여부 |

#### Category (카테고리)

| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 고유 식별자 |
| userId | UUID | 소유 사용자 (FK) |
| name | String | 카테고리명 |
| colorCode | String | 표시 색상 (hex) |
| createdAt | DateTime | 생성일시 |

#### Todo (할일)

| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 고유 식별자 |
| userId | UUID | 소유 사용자 (FK) |
| categoryId | UUID | 소속 카테고리 (FK, nullable) |
| title | String | 할일 제목 |
| description | String | 상세 내용 (nullable) |
| dueDate | DateTime | 종료일시 (nullable) |
| status | Enum | 상태 (PENDING / COMPLETED / OVERDUE) |
| createdAt | DateTime | 생성일시 |
| updatedAt | DateTime | 수정일시 |
| completedAt | DateTime | 완료일시 (nullable) |

### 3.2 도메인 모델 관계

```
User (1) ──< Category (N)
User (1) ──< Todo (N)
Category (1) ──< Todo (N)   [optional]
```

### 3.3 할일 상태 전이

```
PENDING ──[완료 처리]──> COMPLETED
PENDING ──[종료일 경과]──> OVERDUE
OVERDUE ──[완료 처리]──> COMPLETED
COMPLETED ──[완료 취소]──> PENDING
```

## 5. 핵심 비즈니스 규칙

### 인증 및 접근 제어

- **BR-01** 모든 기능은 로그인 인증 후에만 접근 가능하다. (비인증 사용자는 로그인/회원가입 화면만 접근 가능)
- **BR-02** 사용자는 본인 소유의 데이터(할일, 카테고리)만 조회·수정·삭제할 수 있다.
- **BR-03** ADMIN은 모든 사용자의 데이터를 관리할 수 있다.

### 카테고리 규칙

- **BR-04** 카테고리는 사용자별로 독립적으로 관리된다. (다른 사용자와 공유되지 않음)
- **BR-05** 카테고리 삭제 시, 해당 카테고리에 속한 할일의 categoryId는 null로 설정된다. (할일은 삭제되지 않음)
- **BR-06** 동일 사용자 내에서 카테고리명은 중복될 수 없다.

### 할일 규칙

- **BR-07** 종료일(dueDate)이 현재 시각을 경과한 PENDING 상태의 할일은 OVERDUE로 자동 판별된다.
- **BR-08** 할일 완료 처리 시 completedAt이 기록된다.
- **BR-09** 할일의 카테고리는 미지정(null) 상태로 저장 가능하다.
- **BR-10** 할일 제목(title)은 필수 입력값이다.

### 계정 규칙

- **BR-11** username은 시스템 전체에서 고유해야 한다.
- **BR-12** 비활성화된 계정은 로그인할 수 없다.

## 7. 도메인 제약사항

### 데이터 제약

| 항목 | 제약조건 |
|------|---------|
| username | 필수, 영문·숫자 조합, 4~20자, 시스템 유일 |
| password | 필수, 최소 4자 이상 |
| 할일 제목 | 필수, 최대 200자 |
| 할일 상세 | 선택, 최대 1000자 |
| 카테고리명 | 필수, 최대 50자, 사용자 내 유일 |

### 비기능 제약

- **보안**: 비밀번호는 반드시 해시 암호화하여 저장 (평문 저장 금지)
- **인증**: JWT 또는 세션 기반 인증 방식 적용
- **데이터 격리**: 사용자 간 데이터 접근 철저히 분리
- **OVERDUE 판별**: 서버 기준 시각으로 판별 (클라이언트 시각 미사용)

### 초기 데이터

- 시스템 최초 실행 시 ADMIN 계정(`admin` / `admin`)이 자동 생성된다.
- ADMIN 계정은 삭제 및 비활성화할 수 없다.
